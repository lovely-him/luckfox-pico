# U-Boot Proper 加载过程详解

## 你的问题

1. **U-Boot Proper 会验证初始化设备树的所有内容吗？**
2. **"环境加载"具体指什么？**
3. **"内核加载"具体指什么？**
4. **是否是将存储介质的内容复制到 DRAM？**

## 简短回答

### 1. 设备树验证

**不是验证"初始化"所有内容，而是验证"完整性"**：

- ✓ **验证 SHA256 哈希** - 确保设备树没有被篡改
- ✓ **验证格式正确性** - 确保 DTB 格式有效
- ✗ **不会初始化所有硬件** - 只初始化 U-Boot 需要的设备（MMC、UART、GPIO 等）
- ✗ **不会验证所有配置** - 只解析 U-Boot 需要的节点

### 2. 环境加载

**从存储介质读取 U-Boot 环境变量到内存**：

```
存储介质（eMMC/SD/SPI NAND）
    ↓ 读取
环境分区（32KB @ 0x0）
    ↓ 解析
内存中的环境变量表
    ↓ 使用
启动参数、网络配置等
```

### 3. 内核加载

**从存储介质读取内核镜像和设备树到 DRAM**：

```
存储介质（eMMC）
    ↓ 读取
boot 分区（32MB @ 0x8000）
    ↓ 解压/复制
DRAM 中的内核镜像（@ 0x00008000）
DRAM 中的设备树（@ 0x00c00000）
    ↓ 跳转
启动 Linux 内核
```

### 4. 数据复制

**是的，完全正确！** 所有操作都是将数据从存储介质复制到 DRAM：

| 阶段 | 源（存储介质） | 目标（DRAM） | 大小 |
|------|---------------|-------------|------|
| SPL 加载 U-Boot | eMMC @ 0x440 扇区 | 0x00200000 | ~2 MB |
| SPL 加载 U-Boot DTB | eMMC @ 0x440 扇区 | 0x00261190 | ~40 KB |
| U-Boot 加载环境 | eMMC @ 0x0 扇区 | 内存环境表 | 32 KB |
| U-Boot 加载内核 | eMMC @ 0x1f50 扇区 | 0x00008000 | 3.1 MB |
| U-Boot 加载内核 DTB | eMMC @ 0x1f50 扇区 | 0x00c00000 | 40.8 KB |

## 第一部分：设备树验证详解

### U-Boot 对设备树做了什么？

#### 1. SPL 阶段的设备树验证（第 29 行）

```
## Checking fdt 0x00261190 ... sha256(9f596c5683...) + OK
```

**代码位置**：`common/spl/spl_fit.c:spl_load_simple_fit()`

**验证内容**：
- ✓ **SHA256 哈希校验** - 确保 DTB 没有被篡改
- ✓ **FDT 头部验证** - 检查 magic number (0xd00dfeed)
- ✓ **大小检查** - 验证 DTB 大小合理
- ✗ **不解析内容** - SPL 阶段不解析设备树内容

**验证代码**：
```c
// common/spl/spl_fit.c
int spl_load_simple_fit(struct spl_image_info *spl_image,
                        struct spl_load_info *info, ulong sector, void *fit)
{
    // 验证 FDT 哈希
    ret = fit_image_verify_with_data(fit, fdt_offset,
                                     fdt_addr, fdt_len);
    if (ret) {
        printf("## Checking fdt 0x%08lx ... ", fdt_addr);
        printf("sha256(%s...) + OK\n", hash);
    }
}
```

#### 2. U-Boot Proper 阶段的设备树使用（第 37-63 行）

```
Model: Rockchip RV1106 EVB Board        ← 读取 U-Boot DTB
...
DTB: rk-kernel.dtb                      ← 加载内核 DTB
HASH(c): OK                             ← 验证内核 DTB
Model: Luckfox Pico Ultra W             ← 读取内核 DTB
```

**U-Boot 使用自己的 DTB**：
- **位置**：0x00261190
- **用途**：配置 U-Boot 自身的硬件
- **内容**：
  - 启动设备顺序（SD 卡、SPI NAND、eMMC）
  - 串口配置
  - MMC 控制器配置
  - GPIO 配置

**U-Boot 加载内核的 DTB**：
- **位置**：0x00c00000
- **用途**：传递给 Linux 内核
- **内容**：
  - 完整的硬件描述
  - 所有外设配置
  - 驱动程序参数

### 设备树验证 vs 设备初始化

**重要区别**：

| 操作 | 设备树验证 | 设备初始化 |
|------|-----------|-----------|
| **时机** | 加载时立即执行 | 根据需要执行 |
| **范围** | 整个 DTB 文件 | 只初始化需要的设备 |
| **目的** | 确保数据完整性 | 配置硬件工作 |
| **方法** | SHA256 哈希 | 读取寄存器、配置时钟等 |

**U-Boot Proper 初始化的设备**（根据启动日志）：

```
✓ UART2 (0xff4c0000)     - 串口控制台
✓ MMC0 (0xffa90000)      - eMMC 控制器
✓ MMC1 (0xffaa0000)      - SD 卡控制器（尝试）
✓ GPIO (0xff380000)      - GPIO 控制器
✓ GMAC (0xffa80000)      - 以太网控制器
✓ SARADC                 - ADC（用于按键检测）
✓ 时钟树（APLL、DPLL、GPLL、CPLL）

✗ 摄像头、显示屏、USB、音频等 - 不初始化（内核负责）
```

**U-Boot DTB** (`rv1106-luckfox.dtb`):
- **大小**：约 40 KB
- **内容**：U-Boot 需要的最小硬件配置
- **示例**：
  ```dts

      model = "Rockchip RV1106 EVB2 Board";
      chosen {
          stdout-path = &uart2;

  ```

**内核 DTB** (`rv1106g-luckfox-pico-ultra-w.dtb`):
- **大小**：约 40.8 KB
- **内容**：完整的硬件描述
- **示例**：
  ```dts
  / {
      model = "Luckfox Pico Ultra W";
      // 包含所有外设：摄像头、显示屏、USB、音频、WiFi、蓝牙等
  };
  ```

## 第二部分：环境变量加载详解

### 什么是 U-Boot 环境变量？

U-Boot 环境变量是一组**键值对**，用于配置启动行为。类似于 Linux 的环境变量，但存储在非易失性存储器中。

### 启动日志中的环境加载（第 45、50-51 行）

```
Using default environment                    ← 使用默认环境（未找到保存的环境）

ENVF: Primary 0x00000000 - 0x00008000       ← 环境分区位置
ENVF: Primary 0x00000000 - 0x00008000       ← 重复检查（主环境和备份环境）
```

### 环境变量存储位置

**在 eMMC 上的分区布局**（从启动日志第 181 行）：

```
blkdevparts=mmcblk0:32K(env),512K@32K(idblock),256K(uboot),32M(boot),...
                     ↑
                     环境分区：32KB @ 偏移 0
```

**物理地址**：
- **起始扇区**：0（第一个扇区）
- **大小**：32 KB（64 个扇区，每扇区 512 字节）
- **结束扇区**：63

### 环境变量的内容

**常见环境变量**：

```bash
# 启动命令
bootcmd=run distro_bootcmd

# 启动参数
bootargs=console=ttyFIQ0 root=/dev/mmcblk0p7 rootfstype=ext4

# 网络配置
ipaddr=192.168.1.100
serverip=192.168.1.1
ethaddr=00:11:22:33:44:55

# 启动延迟
bootdelay=3

# 设备树文件名
fdtfile=rv1106g-luckfox-pico-ultra-w.dtb
```

**是的，环境加载就是将数据从存储介质复制到 DRAM！**

### 什么是 FIT 镜像？

**FIT** = **Flattened Image Tree**（扁平镜像树）

FIT 镜像是一个**容器格式**，可以包含多个组件：
- **内核镜像**（kernel）
- **设备树**（fdt）
- **Ramdisk**（initrd，可选）
- **配置信息**（conf）

### 内核加载流程

#### 步骤 1：定位 FIT 镜像

**启动日志第 58 行**：
```
RESC: 'boot', blk@0x00001f50
```

- **RESC** = Resource（资源）
- **'boot'** = 资源名称
- **blk@0x00001f50** = 块地址（扇区 0x1f50 = 8016）

**计算物理地址**：
```
扇区 0x1f50 = 8016
物理地址 = 8016 × 512 字节/扇区 = 4,104,192 字节 = 约 4 MB
```

#### 步骤 2：读取 FIT 镜像到内存

**目标地址**：0x0e8d6f40（从启动日志第 121 行）

```
eMMC boot 分区
  扇区 0x1f50 开始
    FIT 镜像（约 3.3 MB）
        ↓ mmc_read()
DRAM
  地址 0x0e8d6f40
    FIT 镜像副本
```

#### 步骤 3：解析 FIT 镜像

**代码位置**：`common/image-fit.c:fit_image_load()`

```c
// common/image-fit.c
int fit_image_load(...)
{
    // 1. 查找 kernel 节点
    noffset = fit_conf_get_kernel_node(fit, conf_noffset);
    
    // 2. 获取 kernel 数据地址
    fit_image_get_data(fit, noffset, &data, &size);
    // data = 0x0e8e1b40 (FIT 镜像内的偏移)
    // size = 3240592 字节 = 3.1 MB
    
    // 3. 获取加载地址
    fit_image_get_load(fit, noffset, &load_addr);
    // load_addr = 0x00008000
    
    // 4. 验证 SHA256 哈希
    fit_image_verify_with_data(fit, noffset, data, size);
    printf("Verifying Hash Integrity ... sha256+ OK\n");
    
    // 5. 复制到目标地址
    memmove((void *)load_addr, data, size);
    printf("Loading Kernel Image from 0x%08lx to 0x%08lx ... OK\n",
           data, load_addr);
}
```

### 为什么要复制三次？

你可能会问：**为什么不直接从 eMMC 读取到 0x00008000？**

**原因**：

1. **FIT 镜像是容器格式**
   - 内核数据在 FIT 镜像内部，不是从头开始
   - 需要先解析 FIT 头部，找到内核数据的偏移

2. **验证需要完整镜像**
   - SHA256 哈希需要完整的内核数据
   - 必须先读取到临时位置，验证后再复制

3. **灵活性**
   - FIT 镜像可以包含多个配置
   - 可以根据启动参数选择不同的内核/设备树组合

```
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 5. 加载并验证设备树                                     │
│    - 读取 fdt 节点的 data、load、hash 属性              │
│    - 验证 SHA256 哈希                                   │
│    - 复制到 0x00c00000                                  │
│    - 打印 "Loading fdt ... OK"                          │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 6. 准备启动参数                                         │
│    - 设置 r0 = 0（保留）                                │
│    - 设置 r1 = 机器类型 ID                              │
│    - 设置 r2 = 0x00c00000（设备树地址）                 │
└─────────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────────┐
│ 7. 跳转到内核                                           │
│    - 打印 "Starting kernel ..."                         │
│    - 跳转到 0x00008000                                  │
│    - 内核开始执行                                       │
└─────────────────────────────────────────────────────────┘
```


## 总结

### 回答你的问题

#### 1. U-Boot Proper 会验证初始化设备树的所有内容吗？

**不会**。U-Boot Proper 只做以下事情：

| 操作 | 是否执行 | 说明 |
|------|---------|------|
| ✓ 验证 DTB 完整性 | 是 | SHA256 哈希校验 |
| ✓ 验证 DTB 格式 | 是 | 检查 FDT magic number |
| ✓ 读取必要的节点 | 是 | model、chosen、mmc、uart 等 |
| ✓ 初始化必要的设备 | 是 | MMC、UART、GPIO、时钟等 |
| ✗ 初始化所有设备 | 否 | 摄像头、显示屏、USB 等由内核初始化 |
| ✗ 验证所有配置 | 否 | 只验证 U-Boot 需要的配置 |

#### 2. "环境加载"具体指什么？

**从存储介质读取 U-Boot 环境变量到内存**：

```
eMMC 环境分区（32KB @ 扇区 0）
    ↓ mmc_read()
DRAM 临时缓冲区
    ↓ CRC32 验证
    ↓ env_import()
内存中的环境变量哈希表
    ↓ 使用
启动命令、网络配置等
```

**关键点**：
- 环境变量存储在 eMMC 的前 32KB
- 包含启动参数、网络配置等键值对
- 如果验证失败，使用编译时的默认环境

#### 3. "内核加载"具体指什么？

**从存储介质读取内核镜像和设备树到 DRAM**：

```
eMMC boot 分区（扇区 0x1f50）
    ↓ mmc_read()
DRAM FIT 镜像（@ 0x0e8d6f40）
    ↓ 解析 + 验证
    ↓ memmove()
DRAM 内核（@ 0x00008000）+ 设备树（@ 0x00c00000）
    ↓ 跳转
Linux 内核开始执行
```

**关键点**：
- 内核和设备树打包在 FIT 镜像中
- 先读取整个 FIT 镜像到临时位置
- 验证 SHA256 哈希后复制到最终位置

#### 4. 是否是将存储介质的内容复制到 DRAM？

**是的，完全正确！** 所有操作都是数据复制：

| 数据 | 源（存储介质） | 目标（DRAM） | 方法 |
|------|---------------|-------------|------|
| U-Boot Proper | eMMC @ 0x440 | 0x00200000 | SPL 的 mmc_read() |
| U-Boot DTB | eMMC @ 0x440 | 0x00261190 | SPL 的 mmc_read() |
| 环境变量 | eMMC @ 0x0 | 内存哈希表 | env_mmc_load() |
| FIT 镜像 | eMMC @ 0x1f50 | 0x0e8d6f40 | mmc_read() |
| 内核镜像 | FIT @ 0x0e8e1b40 | 0x00008000 | memmove() |
| 内核 DTB | FIT @ 0x0e8d7740 | 0x00c00000 | memmove() |

### 性能分析

**U-Boot Proper 时间分解**（总计 795 ms）：

| 阶段 | 时间 (ms) | 百分比 |
|------|----------|--------|
| 初始化 | ~100 | 12.6% |
| MMC 调谐 | 4 | 0.5% |
| 时钟配置 | ~50 | 6.3% |
| 环境加载 | ~50 | 6.3% |
| 内核加载 | ~500 | 62.9% |
| 验证 | ~50 | 6.3% |
| 内存设置 | ~40 | 5.0% |
| **总计** | **795** | **100%** |

**最耗时的操作**：内核加载（62.9%）
- 从 eMMC 读取 3.3 MB 的 FIT 镜像
- 验证 SHA256 哈希
- 复制内核和设备树到最终位置

### 优化建议

1. **使用压缩内核**
   - 当前：未压缩（3.1 MB）
   - 优化：使用 LZ4 压缩（约 1.5 MB）
   - 节省：约 200 ms 读取时间

2. **跳过 SHA256 验证**（仅开发环境）
   - 当前：验证所有镜像
   - 优化：禁用验证（CONFIG_FIT_SIGNATURE=n）
   - 节省：约 50 ms

3. **使用 HS400 模式**
   - 当前：HS200（200 MHz）
   - 优化：HS400（400 MHz）
   - 节省：约 250 ms 读取时间

4. **并行加载**
   - 当前：串行加载内核和设备树
   - 优化：使用 DMA 并行加载
   - 节省：约 100 ms
